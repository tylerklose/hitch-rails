# Work packet: M2.1

## Scope

After every M0/M1 gate is accepted, add the direct `mcp >= 1.1.0, < 2`
runtime dependency and the private `Hitch::MCP::SDKAdapter`. Implement only the
frozen selective structural symbolization, fresh server construction, explicit
non-forwarding callbacks, output validation enablement, and version-scoped gap
normalizers covered by the SDK probe contract.

## Not in scope

- Endpoint HTTP parsing/authentication, registry classes, host tools, Redis, or
  generators.
- SDK transport shortcuts, global callback mutation, copied SDK dispatch code,
  or public compatibility APIs.
- Starting while the auth-only internal `0.1.0` checkpoint evidence is unaccepted.

## Target files/API

- `hitch-rails.gemspec` and SDK appraisal files: direct bounded dependency and
  distinct minimum/latest 1.x lanes.
- `app/models/hitch/mcp/internal/sdk_adapter.rb` and private normalizers.
- `test/hitch/mcp/sdk_contract_test.rb`: executable probes for symbol shape,
  metadata, callbacks, errors, result fields, tool names, and context handoff.
- `bin/ci-sdk` (new): select and assert the requested SDK lane.

`SDKAdapter` and every normalizer are private and excluded from the public API
manifest.

## Dependencies

M1.3 and the complete M0 checkpoint gate are accepted. The toolchain lock and SDK
issue links are unchanged or updated in a dedicated reviewed dependency change.

## Acceptance commands

Run:

```sh
bin/ci-sdk min
bin/ci-sdk latest
bin/rubocop
```

Each lane asserts the loaded `MCP::VERSION`; equal resolved versions remain two
separately named runs. Every normalizer has a failing removal test linked to an
SDK probe/upstream issue.

## Evidence paths

Create `docs/evidence/0.2.0/sdk/gap-ledger.json` with lane resolution, pin,
normalizer IDs, upstream links, test outcomes, and zero global callback changes.

## Rollback

R1: revert dependency, adapter, tests, and evidence together before the
prerelease. Do not leave the gemspec claiming a runtime dependency with no
consumer.

## Estimate

Four engineering days. Risk is high at the private protocol compatibility
boundary.

## Risks

- Deep symbolization enables attacker-controlled symbol growth.
- Per-server callbacks can inherit unsafe globals unless all are overridden.
- The SDK version can resolve differently while lane names still appear green.
- A normalizer can duplicate SDK behavior and corrupt future versions.

## Owner

The Hitch release maintainer owns dependency and normalizer acceptance.
