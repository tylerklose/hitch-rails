# Work packet: M4.2

## Scope

Implement the closed `Hitch::MCP::Result` constructors, output-schema
validation, exact serialized byte cap, SDK validation backstop, and fixed error
normalization. Only explicit `Result.error` messages are public; all unexpected,
invalid, or oversize results become the same generic tool error and are reported
through sanitized `Rails.error` context.

## Not in scope

- Implicit serialization of Hashes, models, exceptions, or arbitrary objects.
- Durable host audit persistence, business diagnostics, streaming, or
  input-required results.

## Target files/API

- `app/models/hitch/mcp/result.rb` and private output validator/normalizer.
- `Hitch::MCP::Result.text`, `.structured`, and `.error` public constructors.
- `test/hitch/mcp/result_test.rb` and SDK callback/error canary tests.

No raw SDK validation detail or host exception is public API.

## Dependencies

M4.1 final schema/policy/perform ordering is accepted.

## Acceptance commands

Run:

```sh
bin/ci-test test/hitch/mcp/result_test.rb
bin/ci-sdk min
bin/ci-sdk latest
```

Tests cover every JSON primitive/container, output-schema mismatch, missing
schema, exact cap boundary, serialization failure, Result.error, exceptions,
and response/log/callback secret canaries.

## Evidence paths

Create `docs/evidence/0.2.0/tool/result-normalization.json` with vector IDs,
serialized sizes, categories, SDK lanes, and zero canary matches.

## Rollback

R1: revert Result/output code and tests together.

## Estimate

Three engineering days. Risk is high because output and error leakage happens
after authorized host execution.

## Risks

- Measuring the pre-serialization object misses wire expansion.
- SDK validation disabled by default permits invalid structured content.
- Convenience coercion can serialize sensitive model attributes.

## Owner

The Hitch release maintainer owns Result and redaction acceptance.
