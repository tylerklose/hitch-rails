# Work packet: M5.4

## Scope

Build the exact gem and install it into disposable SQLite/PostgreSQL apps with a
pinned Redis service. Drive the documented public/confidential OAuth and
discover/list/call/step-up sequence with automated official TypeScript/Python
SDK clients. Verify package contents and every public instruction, then seal
`0.2.0.pre.4` as the first useful end-to-end and public-eligible artifact.
The one-time decision is recorded as `deferred_to_final`. The
`published_pre4` branch remains historical contract context only and cannot be
reopened by M6 or M7.
Product/model clients require separate Tyler approval.

## Not in scope

- Testing via repository `path:`, hidden local files, paid/model-backed smokes
  without approval, or private-host adoption.
- Claiming MySQL or evergreen client compatibility.
- Publishing without explicit release-maintainer approval, or publishing
  `0.2.0.pre.1` through `.pre.3` retroactively.

## Target files/API

- disposable-app builders, pinned Redis service definition, and automated
  official client fixtures.
- `bin/package-apps`, `bin/client-smokes`, and `bin/release-check` (new). The
  release check now keeps prerelease public preflight closed; its live download,
  forbidden-path, and immutable-tag reconciliation path is reserved for final
  `0.2.0`.
- package allowlist and installation/public-document tests.
- machine-readable publication-decision and conditional downloaded-gem evidence.

This proves already documented public API; harnesses are not packaged runtime.

## Dependencies

M5.3 operator/docs gate is accepted and all M0-M4 appraisals/contracts remain
green.

## Acceptance commands

Run:

```sh
bin/package-apps
bin/client-smokes --automated
bin/contract
bin/verify-release-policy
```

Use the built gem in both database apps, the pinned Redis digest, exact docs,
and automated clients. Record model-client smokes only after explicit approval.
The unused historical `published_pre4` branch is retained only in accepted
decision evidence; it has no active publication command. Because the decision
is `deferred_to_final`, the downloaded-gem check is explicitly not applicable
and public preflight fails before tag or network access. M6 installs the exact
accepted internal artifact instead.
Subsequent Hitch-only package CI reconstructs that artifact
from its accepted commit, requires the exact recorded SHA, and permits checkout
drift only in packaged `ROADMAP.md` governance prose; runtime and public
instruction bytes must still match the sealed checkpoint.

## Evidence paths

Create `docs/evidence/0.2.0/package/disposable-apps.json` and
`docs/evidence/0.2.0/clients/automated-smokes.json` with package/client/service
checksums, commands, results, and approval status. Create
`docs/evidence/0.2.0/release/pre4-publication-decision.json` with exactly one
decision and `docs/evidence/0.2.0/release/downloaded-pre4.json` only when
published; otherwise record the conditional check as not applicable in the
decision record.

## Rollback

R1 for an unpublished checkpoint, R3 for preview/canonical route work, and R4
only after public prerelease publication. Dispose test apps/services; never
rewrite published bytes.

## Estimate

Four engineering days. Risk is high because repository-relative tests can hide
broken packages and docs.

## Risks

- A path dependency tests checkout code instead of gem bytes.
- SQLite/PostgreSQL or SDK client lanes can silently diverge.
- Floating Redis/client versions make failures irreproducible.

## Owner

The Hitch release maintainer owns package/checkpoint acceptance, the
publish-or-defer decision, and any public prerelease action; Tyler Klose alone
approves paid/model-backed client smokes.
