# Work packet: M3.2

## Scope

Implement the string-configured `Hitch::MCP::Registry`, descriptor-only
`Hitch::MCP::Tool` surface, and atomic `Rails.application.config.to_prepare`
validation. Store class names and static scopes only, resolve reloadable classes
fresh, reject the complete invalid-entry set, and replace the entire validated
snapshot or serve none of the failed reload.

## Not in scope

- Tool execution/argument policy/results, availability filtering, Redis, policy
  adapters, auto-discovery, or controller-level registry configuration.
- Retaining stale classes after a failed development reload.

## Target files/API

- `app/models/hitch/mcp/registry.rb`, descriptor portions of
  `app/models/hitch/mcp/tool.rb`, and private immutable registry snapshots.
- configuration reader/boot validation and to-prepare integration.
- `test/hitch/mcp/registry_test.rb` and
  `test/hitch/mcp/registry_reload_test.rb`.

`Registry.register` and descriptor DSL entries become public as frozen in the
manifest; execution remains unavailable until M4.

## Dependencies

M3.1 context and per-request handoff are accepted.

## Acceptance commands

Run:

```sh
bin/ci-test test/hitch/mcp/registry_test.rb \
  test/hitch/mcp/registry_reload_test.rb
bin/rubocop
```

Tests cover eager load, duplicates, invalid names/schemas/scopes/annotations,
reserved explicit properties, `.call` overrides, atomic reload, and no stale
class retention.

## Evidence paths

Create `docs/evidence/0.2.0/registry/reload-validation.json` with named invalid
entries, snapshot transitions, concurrency results, and class-name-only storage.

## Rollback

R1: revert registry/descriptor/configuration code and tests together.

## Estimate

Four engineering days. Risk is high because reload and partial validation can
silently expose stale or invalid tools.

## Risks

- Constant objects retained in configuration defeat Rails reload semantics.
- Entry-by-entry mutation can leave a partial registry.
- SDK name validation differs from the frozen host-policy subset.

## Owner

The Hitch release maintainer owns Registry and reload-contract acceptance.
