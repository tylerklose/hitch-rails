# Work packet: M1.3

## Scope

Turn the M1.2 contract into deterministic fixtures. Pin the Ruby SDK,
conformance runner, Lattice implementation, Redis image, mutation runner, and
supporting tools. Freeze exact wire vectors and all twelve exhaustive terminal
authorization paths. Add named pending runtime tests and one `bin/contract`
gate that validates provenance/docs/toolchain, regenerates Lattice with seed 42
at default and strength 8, compares semantic scenarios, and tests the fixtures.

## Not in scope

- Implementing the SDK adapter, endpoint, registry, tool execution, Redis store,
  generators, or conformance host.
- Treating named pending runtime tests as passing runtime evidence.
- Updating the pinned SDK or conformance versions outside a dedicated reviewed
  change with before/after evidence.
- Running paid/model-backed client smokes.

## Target files/API

- `test/conformance/toolchain.lock.yml` and
  `test/conformance/expected-failures.yml`.
- `test/contracts/mcp_wire_vectors.yml`,
  `test/contracts/mcp_tool_authorization_oracles.yml`, and
  `test/contracts/pending_runtime_tests.yml`.
- `test/contracts/mcp_contract_artifacts_test.rb`, plus named pending
  `test/hitch/mcp/sdk_contract_test.rb`,
  `test/integration/mcp_wire_contract_test.rb`, and
  `test/integration/mcp_tool_authorization_lattice_test.rb`.
- `bin/verify-toolchain` and `bin/contract` (new), with
  `test/tooling/verify_toolchain_test.rb` (new).

The fixtures are contract inputs. No runtime gem API is created in this issue.

## Dependencies

M1.2 is accepted with a complete API manifest, threat model, probe ledger, and
mutation-owned invariant set. The accepted M0.5 internal checkpoint remains a
prerequisite for M2; green M1 fixtures do not waive it.

## Acceptance commands

Run:

```sh
bin/contract
bin/verify-release-policy
bin/ci-test test/tooling/verify_toolchain_test.rb \
  test/contracts/mcp_contract_artifacts_test.rb
bin/rubocop
```

The gate must prove the original scenario artifact still matches default
generation and that strength-8 generation yields the identical twelve
`scenarios` rows. It must fail on any pin/hash/oracle/vector/pending-test drift.

## Evidence paths

Create `docs/evidence/0.2.0/contract/contract-verification.json` with pinned
versions, artifact checksums, default/strength-8 row counts, verifier/test
outcomes, and an explicit `runtime_status: pending_m2`. Raw logs remain CI
artifacts.

## Rollback

R1: revert pins, fixtures, gates, tests, and evidence together. Do not leave a
runtime branch consuming an unfrozen or partially reverted contract.

## Estimate

Three engineering days. Risk is high because weak fixture equality or drifting
pins can make later runtime evidence irreproducible.

## Risks

- Comparing generator metadata instead of scenario rows can confuse strength
  changes with behavioral drift.
- A floating container tag or npm range defeats reproducibility.
- Pending tests can be mistaken for implemented behavior unless separately
  named and reported.
- Hand-edited generated rows destroy the Lattice coverage guarantee.

## Owner

The Hitch release maintainer owns lock updates and contract acceptance. The M2
implementer consumes these fixtures but cannot silently rewrite them to match
runtime behavior.
