# Work packet: M5.2

## Scope

Ship the explicit tool generator and final public test helpers. Generate a thin,
namespaced `Hitch::MCP::Tool` subclass with safe schema/policy defaults and a
matching Minitest file, but never edit the registry automatically. Refuse every
constant/file collision and report the one manual registration line.

## Not in scope

- Tool auto-discovery/auto-registration, business model methods, policy adapter
  choice, or semantic audit persistence.
- Overwriting an existing tool or test.

## Target files/API

- `lib/generators/hitch/tool_generator.rb` and templates.
- public test-helper modules frozen in the manifest.
- tool generator/collision/output tests under the shared generator gate.

`hitch:tool NAME` and public helpers are operational API; templates create host
code, not framework business policy.

## Dependencies

M4.5 is accepted. M5.1 may run in parallel but both precede M5.3.

## Acceptance commands

Run:

```sh
bin/ci-generators tool
bin/contract
bin/rubocop
```

Assert real generated output, name normalization, registry non-mutation,
collision refusal, default-deny policy, runnable generated test, and rollback
manifest.

## Evidence paths

Create `docs/evidence/0.2.0/generators/tool.json` with input/output names,
generated checksums, collision cases, and registry unchanged assertions.

## Rollback

R1: revert generator/helpers/tests. Host files are removed only from an exact
unchanged manifest or by operator review.

## Estimate

Two engineering days. Risk is medium because name and registry side effects can
silently broaden exposure.

## Risks

- Name normalization can collide after constantization.
- Auto-registration would bypass explicit review.
- Generated policy methods can accidentally allow by default.

## Owner

The Hitch release maintainer owns tool-generator/helper acceptance.
