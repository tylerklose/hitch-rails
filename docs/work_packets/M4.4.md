# Work packet: M4.4

## Scope

Emit exactly one versioned `request.hitch_mcp` event for every non-OPTIONS
request and one `invocation.hitch_mcp` event only after a registered executable
tool passes SDK input validation. Emit only the frozen structural key sets,
catch/report subscriber failures without changing responses, and replace all
SDK callbacks that could expose arguments, bodies, results, or exceptions.

## Not in scope

- Framework-owned durable audit tables, business analytics, semantic host audit,
  or host instrumentation retention.
- Credentials, bodies, arguments, results, exception messages, or backtraces in
  any Hitch event/callback/log.

## Target files/API

- private request/invocation instrumentation and callback-chain integration.
- public event names and exact version-1 payload contracts.
- `test/hitch/mcp/observation_test.rb`, subscriber-failure tests, callback-order
  tests, and secret canaries.

The two event schemas are public; internal notification helpers are private.

## Dependencies

M4.2 result normalization and M4.3 admission behavior are both accepted.

## Acceptance commands

Run:

```sh
bin/ci-test test/hitch/mcp/observation_test.rb
bin/ci-wire
bin/ci-rate-limit
```

Assert event counts/keys on every terminal path, callback order on early halts,
subscriber isolation, and zero sensitive-key/canary emission.

## Evidence paths

Create `docs/evidence/0.2.0/observation/event-contract.json` with event versions,
key sets, terminal counts, subscriber outcomes, and canary results.

## Rollback

R1: revert instrumentation and tests without altering MCP outcomes.

## Estimate

Two engineering days. Risk is high because observation code sees every boundary
and can itself break or leak a response.

## Risks

- An outer callback installed too late misses early halts.
- Subscriber exceptions can replace the protocol response.
- SDK callbacks can bypass Hitch's event redaction.

## Owner

The Hitch release maintainer owns event schemas and leakage acceptance.
