# Work packet: M0.5

## Scope

Seal the repaired auth substrate as a reproducible internal `0.1.0` checkpoint.
Set the declared Ruby bound to `>= 3.3, < 4.1` and Rails bound to
`>= 7.2, < 8.2`; verify SQLite and PostgreSQL only. Expand the H0 appraisal
bootstrap into the two required 0.1 lanes, aggregate test/lint/zeitwerk/
migration/package checks under root `bin/ci`, and run them in GitHub Actions.

Build the gem from an immutable source commit, verify its manifest and source
bytes, install that exact artifact through a temporary local gem repository into
disposable supported apps, run the auth installer and migrations, boot the
engine, and execute a minimal OAuth/discovery path. Record both the source tree
and package payload digests. The `.gem` container checksum is observed evidence,
not a substitute for the deterministic payload digest.

Ship truthful README, SECURITY, CHANGELOG, source-adoption instructions, and
`docs/public_api/0.1.0.md`. They must say that `0.1.0` is an internal checkpoint
with no public tag, GitHub release, or RubyGems version. The compatibility
surface is exhaustive; everything else is private.

## Not in scope

- Any public gem publication, tag, GitHub release, or installable CI artifact.
- `bin/release-check`; M5.4 owns the first public-download verifier.
- Runtime `mcp` or Redis dependencies; they begin with 0.2.
- MCP registry/tool endpoint or its generators.
- Rails/MySQL support outside the fixed matrix.

## Target files/API

- `hitch-rails.gemspec`: exact Ruby/Rails bounds, truthful SQLite/PostgreSQL
  description, metadata, and an explicit package file allowlist including the
  checkpoint docs while excluding tests, secrets, tmp data, and work evidence.
- `Gemfile`, `gemfiles/rails_7_2_sqlite.gemfile`, and
  `gemfiles/rails_8_1_postgresql.gemfile`: align development/test dependencies
  with the checkpoint while keeping `mcp` test-only for 0.1.
- `bin/ci` (new): fail-fast aggregate entrypoint for the current suite,
  RuboCop, Zeitwerk, packet/policy validation, migration checks, and both
  appraisal profiles.
- `bin/package-smoke` (new): local built-gem adoption from a temporary gem
  repository, byte/manifest checks, and disposable supported applications.
- `bin/verify-release-policy` (new): validate the machine-readable distribution
  graph, explicit `published: false` state, immutable source identity, evidence
  references, conformance classifications, and acceptance completeness.
- `.github/workflows/ci.yml`: Ruby 3.3/Rails 7.2/SQLite and Ruby 4.0/Rails
  8.1/PostgreSQL lanes, checkpoint/package gates, non-installable package reports,
  and sanitized authorization-conformance evidence.
- `lib/hitch/version.rb`, `CHANGELOG.md`, `README.md`, `SECURITY.md`, and
  `docs/public_api/0.1.0.md`: one internal checkpoint identity and contract.
- `docs/upgrading/0.1.0.md` and `docs/removing.md`: normalized redirect
  cutover/rollback and non-destructive source-adoption guidance.

The documented generators/tasks, configuration, and checkpoint API entries are
the supported compatibility surface. CI/checkpoint internals and evidence
serializers are private.

## Dependencies

- M0.4 is accepted, so M0.1 through M0.4 behavior, migrations, HTTP posture, and
  prose evidence are complete.
- H0 appraisal manifests are the starting profiles; this issue expands their CI
  use and creates every new command/evidence path named here.
- Public distribution is intentionally deferred and is not an M0 or M1
  dependency.

## Acceptance commands

From the exact clean source checkpoint run:

```sh
bin/ci
bin/package-smoke
bin/verify-release-policy --acceptance
```

The package smoke must install the just-built artifact, not a repository path.
Compare the embedded gem manifest and extracted contents with the allowlist and
source bytes; prove no credentials, work evidence, logs, or tmp files are
packaged. Both exact CI lanes must be green with no unexplained skips. The
acceptance verifier must fail if source identity is missing, a hosted lane is
pending, public distribution is claimed, the conformance classifications are
collapsed, or any evidence record belongs to different bytes.

## Evidence paths

Create:

- `docs/evidence/0.1.0/checkpoint/ci-matrix.json` for exact lane versions/checks;
- `docs/evidence/0.1.0/checkpoint/package-manifest.json` for source/tree/payload
  identity plus built-gem file names, modes, sizes, and checksums;
- `docs/evidence/0.1.0/checkpoint/disposable-apps.json` for generated app commands
  and outcomes;
- `docs/evidence/0.1.0/checkpoint/publication-status.json` with
  `published: false`, null public artifact/tag fields, and the M5 policy; and
- `docs/evidence/0.1.0/checkpoint/completion.json` tying the accepted source
  commit/tree to every required sanitized evidence record.

Credential-bearing authorization-runner output is destroyed on the isolated
runner and never uploaded; only sanitized official-metadata and reviewed-
extension summaries and raw-file hashes are retained. Evidence contains no
credentials, machine-specific home paths, or database contents.

## Rollback

R1: an internal checkpoint can be superseded by a newly verified source commit;
never relabel changed bytes with the accepted checkpoint identity. Retain
migration compatibility so code rollback follows M0.3b's operator procedure.

## Estimate

Three engineering days plus exact-matrix time. Risk is high because this
turns a source commit into an immutable evidence baseline even though it creates
no public distribution state.

## Risks

- A green root bundle can hide a broken lower-bound or SQLite install.
- `gemspec` globbing can omit generators/migrations/docs or package private
  evidence and local files.
- A package smoke using `path:` tests checkout code instead of artifact bytes.
- A moving or dirty checkout cannot reconstruct an accepted checkpoint.
- Uploading the `.gem` from public CI would create distribution before M5 even
  without RubyGems.

## Owner

The Hitch release maintainer owns internal checkpoint acceptance and evidence
review. Contributors may implement automation and docs but may not create public
tags, releases, uploads, or RubyGems state without explicit authority.
