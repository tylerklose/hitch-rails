# Work packet: M2.3

## Scope

Pin and run the official server/auth conformance harness against a disposable
host. Register only the five fixture tools, apply the reviewed resource and
Authorization harness-only patch, run the named applicable scenarios, preserve
exactly two check-level expected failures, and report capability-gated skips and
the excluded mixed-feature caching scenario without calling them passes.

## Not in scope

- Shipping fixture tools or patches in generated/production applications.
- Altering official scenario assertions or widening the expected-failure file.
- Claiming all-server-suite conformance, subscriptions, prompts, or resources.
- Public distribution; `0.2.0.pre.1` is an internal checkpoint only.

## Target files/API

- `bin/conformance-bootstrap` and `bin/conformance-server` (new).
- `test/conformance/package-lock.json`, harness-only patch/checksum, fixture host,
  and `expected-failures.yml`.
- conformance result parser/tests that fail on new failure, stale baseline, or
  a baseline entry becoming a demonstrated pass.

All harness code is test infrastructure, never packaged runtime API.

## Dependencies

M2.2 passes every Hitch-owned wire vector in both SDK lanes and the M1.3
toolchain pins are unchanged.

## Acceptance commands

Run:

```sh
bin/conformance-bootstrap
bin/conformance-server
bin/ci-wire
```

Evidence distinguishes official unmodified scenarios, extended auth harness
checks, expected failures, capability skips, and explicit exclusions.

## Evidence paths

Create `docs/evidence/0.2.0/conformance/server-checks.json` and
`docs/evidence/0.2.0/conformance/auth-extension.json`, both redacted and linked
to exact runner/patch checksums.

## Rollback

R1: supersede the internal `0.2.0.pre.1` checkpoint only with newly verified
bytes. Never rewrite accepted baseline history.

## Estimate

Three engineering days. Risk is high because harness limitations can be
misreported as product support.

## Risks

- A floating npm install invalidates comparisons.
- Fixture-only tools can accidentally enter the gem manifest.
- Broad scenario-level allowlisting hides new check failures.
- Capability skips can be counted as successes in summary output.

## Owner

The Hitch release maintainer owns baseline review and internal
`0.2.0.pre.1` checkpoint acceptance.
