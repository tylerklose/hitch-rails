# Work packet: M3.1

## Scope

Implement `Hitch::MCP::Context` as a request-local frozen envelope and the exact
SDK handoff `{ hitch_context: context }`. Recursively copy/freeze untrusted
metadata, preserve host/Active Record references as opaque request-local values,
and retrieve context only with `server_context.fetch(:hitch_context)`.

## Not in scope

- Registry/reload behavior, arbitrary tools, argument policy, results, Redis,
  or generators.
- Rails `Current`, class variables, shared servers, or claims that referenced
  records are immutable.

## Target files/API

- `app/models/hitch/mcp/context.rb`: documented public readers and construction
  errors.
- private context builder and SDK handoff integration.
- `test/hitch/mcp/context_test.rb` and both SDK-lane contract assertions.

`Context` is public but direct mutable construction is not required; the
endpoint supplies validated values.

## Dependencies

M2.3 is accepted with the authenticated wire slice and conformance evidence.

## Acceptance commands

Run:

```sh
bin/ci-test test/hitch/mcp/context_test.rb
bin/ci-sdk min
bin/ci-sdk latest
```

Tests prove cross-request isolation, recursive metadata copy/freeze, optional
client info, no authority from client metadata, and exact wrapper retrieval.

## Evidence paths

Create `docs/evidence/0.2.0/context/sdk-handoff.json` with lane versions,
isolation cases, wrapper assertions, and no credential/body data.

## Rollback

R1: remove context/handoff changes and their tests together.

## Estimate

Two engineering days. Risk is medium because shared context would cross
principal boundaries.

## Risks

- Freezing the envelope can be overstated as freezing referenced records.
- A shallow metadata copy permits later mutation.
- SDK `_meta` can overwrite host context when shapes are conflated.

## Owner

The Hitch release maintainer owns context and SDK-handoff acceptance.
