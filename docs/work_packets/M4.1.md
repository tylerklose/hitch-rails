# Work packet: M4.1

## Scope

Complete the final `Hitch::MCP::Tool` call path. After SDK input-schema
validation, convert arguments to recursively frozen string-keyed JSON, run
deny-default `.authorize!`, then `.perform`. The framework-owned `.call` stays
final; policy denial becomes one generic tool error and performs no host work.

## Not in scope

- Result serialization/output caps, Redis admission, observation events,
  policy-adapter registries, or business transactions/idempotency.
- Passing arguments as Ruby keyword authority or exposing exception messages.

## Target files/API

- final call path in `app/models/hitch/mcp/tool.rb` and public
  `Hitch::MCP::Forbidden`.
- private argument normalizer/freezer and policy error translation.
- `test/hitch/mcp/tool_test.rb` with schema-before-policy and denial mutation
  oracles.

Public `.authorize!` and `.perform` match the frozen manifest; `.call` is
framework-owned and not overridable.

## Dependencies

M3.3 deterministic filtered listing and request isolation are accepted.

## Acceptance commands

Run:

```sh
bin/ci-test test/hitch/mcp/tool_test.rb
bin/ci-sdk min
bin/ci-sdk latest
```

Tests prove schema-before-policy, frozen string keys, nested reserved-key
acceptance, top-level reserved-key pre-SDK rejection, zero execution on denial,
and generic exception-safe responses.

## Evidence paths

Create `docs/evidence/0.2.0/tool/authorization-denials.json` with named denial
paths, work counters, and mutation outcomes without arguments/results.

## Rollback

Three engineering days. Risk is high because ordering mistakes bypass schema or

- Policy messages can become accidental public errors.
