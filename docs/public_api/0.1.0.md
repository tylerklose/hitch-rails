# hitch-rails internal 0.1.0 checkpoint API

This file is the exhaustive compatibility surface captured by the internal
`0.1.0` checkpoint. The checkpoint is not tagged or published to RubyGems.
Anything included in its gem artifact but not named here is an implementation
detail and may change before the first public 0.2 release. Standard Rails model
APIs are not made public merely because Hitch models inherit from
`ActiveRecord::Base`.

## Compatibility contract

- Ruby `>= 3.3, < 4.1`.
- Rails `>= 7.2, < 8.2`.
- SQLite and PostgreSQL are the supported database adapters. MySQL is not.
- `Hitch::VERSION` is the internal checkpoint artifact identity (`"0.1.0"`).
- The host owns its `/mcp` route, tool registry, tool implementation, and
  business authorization policy. Hitch 0.1 owns OAuth, discovery, bearer-token
  validation, and a deprecated compatibility helper for basic Streamable HTTP
  response shaping.

## Configuration

`Hitch.configure { |config| ... }` yields and returns the singleton
`Hitch::Configuration`. `Hitch.configuration` returns that object.

The following configuration readers and writers are supported:

| Setting | Default | Contract |
| --- | --- | --- |
| `resource_uri` | required | Canonical MCP resource URI. HTTPS is required outside development/test loopback. Maximum 2,048 bytes. Its origin fixes Hitch's issuer and endpoint URLs. |
| `allowed_hosts` | `[]` | Additional exact ingress hostnames or IP literals. These are accepted aliases; they never change the canonical issuer. No schemes, ports, paths, wildcards, or trailing dots. |
| `allowed_origins` | `[]` | Exact canonical HTTP(S) browser origins. Production never infers origins; development/test additionally allow loopback origins. |
| `brand_name` | `"Rails MCP"` | Consent-screen display name. |
| `supported_scopes` | `["mcp"]` | One to 32 unique OAuth scope tokens, at most 64 bytes each and 255 bytes after joining with spaces. The server never grants an unconfigured scope. |
| `principal_method` | `:current_user` | Controller method used to find the signed-in principal. Rails 8 `Current.user` is the fallback when that method is absent. |
| `login_path` | `nil` | String or request callable used for unauthenticated authorization. `nil` returns `401`. |
| `access_token_lifetime_seconds` | `3600` | Issued-token lifetime. |
| `authorization_code_lifetime_seconds` | `600` | Authorization-code lifetime. |
| `client_id_metadata_enabled` | library: `false`; generated initializer: `true` | Advertise and resolve Client ID Metadata Documents. Requires direct outbound HTTPS egress. |
| `client_id_metadata_cache_ttl` | `3600` | Maximum positive CIMD cache lifetime in seconds. |
| `client_id_metadata_max_concurrent_fetches` | `4` | Per-process in-flight CIMD ceiling. `nil` disables; zero blocks. |
| `client_id_metadata_fetches_per_minute` | `20` | Per-process, per-principal fixed-window CIMD ceiling. `nil` disables. |
| `dynamic_client_registration_enabled` | library: `true`; generated initializer: `false` | Controls DCR routing behavior and discovery advertisement. The compatibility fallback is deprecated; set this explicitly. |
| `dynamic_client_registration_limit` | `{ to: 20, within: 60 }` | Positive fixed-window registration-attempt bound. |
| `dynamic_client_registration_rate_store` | `nil` | Production DCR store. It must return `true` from `shared?` and implement atomic `increment_with_expiry(key:, expires_in:)`, returning the positive post-increment integer. |

Invalid configuration raises `ArgumentError` or
`Hitch::ResourceUri::Invalid`. The documented finite limits are Hitch's
opinionated protocol/storage contract; they are not claims about every host
database's native text-column maximum.

The supported configuration-bound constants are:

- `Hitch::Configuration::MAX_RESOURCE_URI_BYTES` (`2_048`)
- `Hitch::Configuration::MAX_SCOPES` (`32`)
- `Hitch::Configuration::MAX_SCOPE_BYTES` (`64`)
- `Hitch::Configuration::MAX_SCOPE_SET_BYTES` (`255`)

`Hitch.reset_configuration!`, `Configuration#validate!`, and
`#dynamic_client_registration_enabled_configured?` are framework/test
internals, not public adopter APIs.

## Installation and routes

`bin/rails generate hitch:install` is the supported generator. It creates
`config/initializers/hitch.rb`, idempotently mounts `Hitch::Engine` at `/`, and
prints the required migration step. Run `bin/rails db:migrate` after installing
or upgrading.

The mounted engine supports:

| Endpoint | Success behavior | Stable failure boundary |
| --- | --- | --- |
| `GET/POST /oauth/authorize` | Consent and authorization-code redirect with RFC 9207 `iss`. | OAuth error or `401`; unsafe redirect targets are not followed. |
| `POST /oauth/token` | JSON bearer token response. | OAuth JSON errors; form-only, 16 KiB body limit, singular scalar security parameters. |
| `POST /oauth/revoke` | Empty `200`, including unknown tokens per RFC 7009. | Malformed, query, nested, duplicate, or wrong-media requests remain non-oracular `200` and do no token lookup. |
| `POST /oauth/register` | RFC 7591 JSON response when explicitly enabled. | `404` when disabled; otherwise JSON-only, 16 KiB body limit, strict duplicate-name rejection, and bounded metadata. |
| `GET /.well-known/oauth-authorization-server` | RFC 8414 metadata. | Host validation runs before URL construction. |
| `GET /.well-known/oauth-protected-resource[/<path>]` | RFC 9728 metadata for the one configured resource. | Host validation runs before URL construction. |
| `OPTIONS` for the routes above | `204` only for an allowed origin, route method, and request-header set. | `403` for denied preflights; unknown paths remain `404`. |

Dynamic registration accepts one JSON object. `client_id` and `client_name` are
at most 255 bytes; `redirect_uris` contains 1 to 32 unique, non-empty strings
of at most 255 bytes each; `application_type` and
`token_endpoint_auth_method` must be strings when present. Redirects must be
HTTPS or RFC 8252 loopback HTTP, with no fragment or userinfo.

## Legacy host controller concerns (deprecated)

`Hitch::ServerEndpoint` remains supported through the 0.2 line for existing
integrations, but is deprecated in favor of the authenticated Hitch endpoint
planned for 0.2. It does not provide SDK integration, a registry, or tool
dispatch. Including it in a dedicated host MCP controller exposes this narrow
controller extension surface:

- `require_mcp_token!` as a `before_action`. It accepts one case-insensitive
  `Bearer` credential of at most 512 URL-safe bytes, validates token activity
  and exact resource audience, sets `mcp_token`, or renders `401` with the MCP
  discovery challenge.
- `mcp_token`, returning the validated `Hitch::AccessToken` or `nil` before
  authentication.
- `render_mcp_response(body, session_id: nil)`, rendering empty responses as
  `202`, non-empty serialized JSON as `200 application/json`, and optionally
  setting `Mcp-Session-Id`.

`Hitch::ServerEndpoint::MAX_BEARER_TOKEN_BYTES` (`512`) is a supported bound.
The other concern methods are private implementation details.

Including `Hitch::CorsSupport` is supported for host-owned browser-facing MCP
controllers. Inclusion applies Hitch's configured exact-origin response
policy. Its individual helper methods and constants are private API.

## Token API

The following `Hitch::AccessToken` surface is supported:

- `.find_by_token(raw_token)` returns an active token or `nil`. It never
  accepts a digest as a substitute for the raw bearer token.
- `#accessible?` returns a boolean for issued, unexpired, unrevoked state.
- `#has_scope?(scope)` performs exact membership in the persisted
  space-delimited scope set and returns a boolean.
- `#valid_for_resource?(resource_uri)` canonicalizes both sides and returns a
  boolean; invalid or mismatched resources return `false`.
- `#revoke!` persists `revoked_at` and returns the normal Active Record update
  result; database errors propagate.
- `.cleanup_expired!(revoked_retention_days: 30)` deletes stale pending codes,
  old revoked tokens, and old expired tokens, and returns the number of rows
  deleted.
- Read access to `principal`, `client_id`, `client_name`, `resource_uri`,
  `scopes`, `expires_at`, and `revoked_at` on a token returned by
  `.find_by_token` is supported.

Authorization-code creation/exchange, digest columns, pending/active scopes,
`raw_authorization_code`, `Hitch::Pkce`, and `Hitch::AccessToken::OAuthError`
are owned by Hitch's controllers and are not public host APIs in 0.1.

## Client provisioning API

The following `Hitch::Client` surface is supported for operator tooling:

- `.register!(client_id:, client_name:, redirect_uris:, application_type: nil)`
  creates a public client and returns it.
- `.register_confidential!(...)` creates a confidential client and returns a
  one-time `Hitch::Client::Credentials` object.
- `#public_client?`, `#confidential_client?`, and
  `#authenticates_secret?(candidate)` return booleans.
- `#rotate_secret!` returns new one-time credentials and raises
  `ArgumentError` for a public client.
- `#redirect_uris` returns the authoritative URI array;
  `#replace_redirect_uris!(values)` replaces it transactionally and returns
  the authoritative array.
- Read access to `client_id`, `client_name`, `application_type`,
  `token_endpoint_auth_method`, `client_secret_issued_at`, and
  `client_secret_rotated_at` is supported. The digest is never public.

Registration methods raise
`Hitch::Client::InvalidRegistrationMetadata` for invalid shape or bounds and
may raise ordinary Active Record persistence errors. Supported constants are:

- `TOKEN_ENDPOINT_AUTH_METHODS` (`["none", "client_secret_basic"]`)
- `APPLICATION_TYPES` (`["native", "web"]`)
- `CLIENT_SECRET_BYTES` (`48`)
- `MAX_CLIENT_ID_BYTES` (`255`)
- `MAX_CLIENT_NAME_BYTES` (`255`)
- `MAX_REDIRECT_URIS` (`32`)
- `MAX_REDIRECT_URI_BYTES` (`255`)

`Hitch::Client::Credentials#client` and `#client_secret` are supported only on
the immediate return value. `#inspect` and `#to_s` redact the secret.
`#to_h`, `#as_json`, and `#to_json` always raise
`Hitch::Client::Credentials::SerializationForbidden`; this is a safety
contract, not a serialization format.

## Rake and repository operations

These tasks are public operational surface:

- `hitch:clients:create_confidential` requires `CLIENT_ID` and `REDIRECT_URI`;
  optional `NAME`. It discloses once to an interactive terminal or a new
  mode-`0600` `OUTPUT_FILE`, refuses overwrite, and rolls back the client if
  disclosure or flush fails.
- `hitch:clients:rotate_secret` requires `CLIENT_ID` and has the same one-time
  disclosure and rollback contract.
- `hitch:redirects:cutover` requires all old redirect writers to be drained;
  it verifies parity before making normalized rows authoritative.
- `hitch:redirects:prepare_rollback` requires all redirect writers to be
  drained; it verifies legacy/normalized parity before restoring legacy
  authority for a code rollback.
- `hitch:cimd:check[URL]` exercises the real bounded fetch path and returns
  process status zero only for a usable document. It never changes discovery
  configuration.
## Deprecations and private API

Dynamic Client Registration is deprecated by MCP 2026-07-28. Hitch supports it
in 0.1 only when explicitly enabled; new installations use CIMD instead. The
library's enabled DCR fallback exists solely for unreleased-install
compatibility and will change in a breaking release.

`Hitch::ServerEndpoint` and its companion `Hitch::CorsSupport` concern are
deprecated compatibility surfaces. They remain functional through 0.2 so
existing host-owned endpoints can migrate to the authenticated Hitch MCP
endpoint without an abrupt removal.

All controllers, views, persistence schema, migrations, query scopes,
normalization helpers, CIMD resolver classes, rate-limit implementation,
schema-state classes, exception types not explicitly named above, and
constants/methods not explicitly listed above are private. Override only the
documented consent view and use only the public surface above.
