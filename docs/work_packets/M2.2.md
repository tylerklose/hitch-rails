# Work packet: M2.2

## Scope

Build the authenticated final-2026 POST slice around one hard-coded read-only
tool. Enforce Host/Origin/method/auth/rate callback order, bounded single-message
JSON parsing, modern metadata and standard headers, typed method/name equality,
reserved top-level `server_context` rejection, frozen verified requests, tools-
only dispatch, final response normalization, and exact HTTP/protocol mappings.

## Not in scope

- Public Registry/Tool APIs, arbitrary host tools, production Redis, generators,
  or adoption.
- GET/SSE, initialization, notifications, prompts, resources, tasks, multiple
  surfaces, or legacy sessions.
- Reusing `MCP::Server#handle_json` or `StreamableHTTPTransport`.

## Target files/API

- `app/controllers/concerns/hitch/mcp/endpoint.rb` and private verified-request,
  body-reader, header, normalizer, and hard-coded slice-tool classes.
- protected-resource metadata and generated-controller contract changes.
- `test/integration/mcp_wire_contract_test.rb` and focused unit tests for every
  forced wire vector and SDK callback canary.
- `bin/ci-wire` (new): run exact fixture-to-response assertions.

Only `Hitch::MCP::Endpoint` is planned public here; all parsing/adapter values
remain private.

## Dependencies

M2.1 is accepted in minimum/latest SDK lanes and every M0/M1 checkpoint gate
remains green.

## Acceptance commands

Run:

```sh
bin/ci-wire
bin/ci-sdk min
bin/ci-sdk latest
bin/rubocop
```

Each named wire fixture asserts status, headers, protocol shape, body/registry/
SDK/host work counts, one request event, and no raw error/callback leakage.

## Evidence paths

Create `docs/evidence/0.2.0/wire/http-vectors.json` with redacted named-vector
results, both SDK lanes, byte caps, and canary outcomes.

## Rollback

R1: remove the new endpoint and direct dependency consumers together; preserve
the deprecated legacy endpoint until the documented 1.0 removal window.

## Estimate

Five engineering days. Risk is high because precedence and response mapping are
externally observable security behavior.

## Risks

- Rails parameter parsing can collapse duplicate security keys.
- Parsing before admission spends attacker-controlled work.
- Error data or callback payloads can leak bodies/arguments.
- An unrelated Rails 404 can mask the required endpoint 405.

## Owner

The Hitch release maintainer owns wire acceptance. M2 contributes to the
internal `0.2.0.pre.1` checkpoint and creates no public distribution state.
