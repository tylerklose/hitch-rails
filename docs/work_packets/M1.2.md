# Work packet: M1.2

## Scope

Freeze the 0.2 architecture contract from standards, the M1.1 dossier, and
repeatable Ruby SDK 1.1.0 probes. Decide the endpoint/SDK boundary, request
normalization, reserved-key rule, tool-name subset, callback isolation, reload
ownership, rate-key construction, wire/error precedence, and exact observation
payloads. Give every public method and event input, output, error, and reload
behavior, and give every security invariant a named mutation and killing test.

## Not in scope

- Implementing `Hitch::MCP`, adding the runtime `mcp`/Redis dependencies, or
  changing the legacy endpoint.
- Claiming SDK behavior that was not reproduced or linked upstream.
- Adding a policy adapter, audit table, distributed concurrency lease, prompts,
  resources, tasks, or another MCP surface.
- Starting M2 before the M0 internal checkpoint gate is accepted.

## Target files/API

- `docs/adr/0001-mcp-sdk-boundary.md`, `0002-registry-and-reload.md`,
  `0003-tool-policy-and-errors.md`, and `0004-rate-limit-and-observation.md`.
- `docs/architecture/mcp-data-flow.md` and `docs/security/mcp-threat-model.md`.
- `docs/contracts/mcp_public_api.yml`: exhaustive planned 0.2 constants,
  configuration, methods, events, generators, and operator commands.
- `docs/contracts/mcp_invariants.yml`: source targets, mutation vectors, and
  killing tests for each invariant.
- `docs/contracts/sdk_probes.yml`: observed SDK behavior, exact upstream issue
  links, disposition, and planned test.
- `bin/verify-doc-contract` (new) and
  `test/tooling/verify_doc_contract_test.rb` (new).

The manifest describes future public API; it does not make unimplemented
constants callable. ADRs keep `Hitch::MCP::SDKAdapter` private.

## Dependencies

M1.1 is accepted with exactly two independent roots and a complete extraction
matrix. Standards and the pinned SDK source remain higher authority than host
examples.

## Acceptance commands

Run:

```sh
bin/verify-doc-contract
bin/ci-test test/tooling/verify_doc_contract_test.rb
bin/rubocop
```

The verifier must reject incomplete public entries, missing SDK links,
unclassified probes, event payloads containing sensitive fields, invariants
without mutations/killing tests, or ADRs that describe the private adapter as
public SDK conformance.

## Evidence paths

Create `docs/evidence/0.2.0/contract/document-contract-verification.json` with
manifest/invariant/probe counts, document checksums, exact verifier/test
outcomes, and the M0 checkpoint-gate status. No request bodies or private paths.

## Rollback

R1: revert the contract documents, schemas, verifier, tests, and evidence as one
unit before runtime work. If M2 has started, stop it before changing these
decisions.

## Estimate

Three engineering days plus security/release review. Risk is high because these
decisions assign every public and security boundary implemented later.

## Risks

- Recursive symbolization can turn attacker strings into immortal symbols.
- SDK callbacks or transport shortcuts can receive raw arguments and bodies.
- A reloadable registry can retain stale classes or partially accept entries.
- Error specificity can disclose registry, scope, policy, or exception data.
- Telemetry schemas can drift into argument/result logging without exact keys.

## Owner

The Hitch release maintainer owns API and ADR acceptance; the security reviewer
owns the threat checklist. Contributors may reproduce probes and draft
decisions but may not relabel SDK gaps as conformance.
