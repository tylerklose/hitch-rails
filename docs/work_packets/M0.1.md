# Work packet: M0.1

## Scope

Repair the public-client authorization-code flow before the first tag. Parse the
fixed authorization-query and token-form scalar sets before business logic,
require Authorization Code plus PKCE S256, and bind every authorization code to
its scalar public `client_id` and canonical MCP resource. The authorization and
token requests must carry the same canonical resource. Validate a supplied
legacy token `redirect_uri` for scalar shape only; do not use it for binding.

Scalar validation inspects raw URL-encoded query/body pairs before Rails
parameters collapse duplicate keys. Count an allowed security name across query
and body, reject repeated names and bracketed variants, and reject a token form
with the wrong content type before model lookup. Preserve/rewind the request body
for later consumers.

Use one resource canonicalizer for configuration and inbound values. It must
lowercase scheme and host, remove default ports, reject relative URIs,
fragments, and userinfo, preserve path/query semantics, and permit HTTP only for
an explicit loopback development resource. Client, resource, and PKCE failures
must happen before code consumption, so a corrected retry can still succeed.

## Not in scope

- Confidential-client secrets or HTTP Basic authentication; M0.2 owns them.
- Redirect storage normalization or compare-and-swap consumption; M0.3a and
  M0.3b own those changes.
- DCR enablement, rate limiting, CORS configuration, or prose cleanup; M0.4 owns
  them.
- MCP endpoint, registry, tool, or SDK behavior.

## Target files/API

- `app/controllers/hitch/authorizations_controller.rb`: parse only the fixed
  query set, require `response_type=code`, scalar `client_id`, PKCE S256, and a
  canonical resource before issuing a code.
- `app/controllers/hitch/tokens_controller.rb`: parse only the fixed form set,
  require scalar public `client_id`, and compare client/resource/PKCE before
  consumption. Return OAuth errors without leaking stored values.
- `app/models/hitch/oauth_request_parameters.rb` (new): raw pair parser and
  immutable allowed-parameter result; it must not treat collapsed Rails
  `params` as duplicate evidence.
- `app/controllers/concerns/hitch/oauth_parameter_validation.rb` (new): map the
  parser's private invalid-request exception to the existing OAuth error shape.
  These private constants must match Zeitwerk's default inflection (for example,
  `Hitch::OauthRequestParameters`) unless the engine installs loader-local
  mappings; never mutate a host application's global inflections.
- `app/controllers/concerns/hitch/uri_validation.rb`: keep redirect validation
  separate from MCP resource canonicalization.
- `app/models/hitch/resource_uri.rb` (new): define the single
  `Hitch::ResourceUri.canonicalize!` implementation used by configuration and
  both OAuth endpoints. Its invalid-value exception is translated only at the
  HTTP boundary.
- `app/models/hitch/access_token.rb`: persist the canonical resource and client
  binding on authorization and expose comparisons needed before consumption.
- `lib/hitch/configuration.rb` and `lib/hitch.rb`: validate and document the
  canonical configured resource without introducing a second normalization
  path.
- `test/integration/oauth_flow_test.rb`,
  `test/integration/oauth_security_poc_test.rb`, and
  `test/hitch/access_token_test.rb`: extend the real controller/model boundary
  coverage. Add `test/integration/oauth_request_validation_test.rb` for raw
  query/form parsing and `test/hitch/resource_uri_test.rb` for canonicalization.

The only new candidate public constant is `Hitch::ResourceUri`; M0.5's public
API manifest must either document it or mark it private before release. Scalar
parsing helpers remain private controller mechanism.

## Acceptance commands

Run:

```sh
bin/ci-test test/integration/oauth_flow_test.rb \
  test/integration/oauth_security_poc_test.rb \
  test/integration/oauth_request_validation_test.rb \
  test/hitch/access_token_test.rb \
  test/hitch/resource_uri_test.rb
```

The issue creates both new test files before running the command.
The tests must prove: missing public `client_id` is `invalid_request`; a
different client is `invalid_grant`; missing/mismatched/invalid resources fail;
canonical-equivalent resources succeed; bad PKCE fails; every failed binding
attempt leaves the code redeemable by the original client; duplicate, array,
hash, blank optional, and non-string security parameters fail before lookup;
and omitted token `redirect_uri` succeeds.

Also run `bin/rubocop` and `RAILS_ENV=test bundle exec rake app:zeitwerk:check`.

## Evidence paths

Create `docs/evidence/0.1.0/auth-core.json` in this issue. Record the commit,
Ruby/Rails versions, commands, exit statuses, test counts, and named negative
vectors above. Do not include codes, verifiers, tokens, redirect queries, or
other credential-shaped values. Credential-bearing raw logs remain ephemeral
and are never uploaded; CI may retain only sanitized summaries and hashes.

## Rollback

R1: revert the code and tests together. This issue makes no schema change and
publishes no artifact. If a later issue has begun, revert through the normal
dependency chain rather than leaving two resource-normalization paths.

## Estimate

Three engineering days. Risk is high because client/resource binding and
failure precedence protect authorization codes at the public token boundary.

## Risks

- Rails parameter coercion can hide duplicate or structured inputs unless tests
  exercise the actual request parser.
- URI libraries may normalize path/query data beyond the fixed contract.
- Consuming the code before all checks turns ordinary client correction into a
  denial of service and can mask cross-client redemption defects.
- Updating source comments without the final M0.4 prose audit can leave stale
  security claims; note those locations for M0.4.

## Owner

The Hitch release maintainer is accountable. Implementation may be delegated to
an unfamiliar contributor; the release maintainer accepts the security vectors
and redacted evidence.
