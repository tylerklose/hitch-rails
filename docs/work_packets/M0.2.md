# Work packet: M0.2

## Scope

Add the fixed confidential-client profile without weakening the public-client
path from M0.1. Support `client_secret_basic` only, generate a high-entropy
secret once, persist only its SHA-256 digest and lifecycle timestamps, compare
digests in constant time, and invalidate the old digest transactionally on
rotation. Metadata advertises exactly `none` and `client_secret_basic`.

Provide the roadmap's operator API and tasks:
`Hitch::Client.register_confidential!`, `client.rotate_secret!`,
`hitch:clients:create_confidential`, and `hitch:clients:rotate_secret`. The
return value exposes the persisted client and one-time plaintext secret. Tasks
write the secret to `/dev/tty` only in an interactive terminal; automation must
supply a new `OUTPUT_FILE`, created exclusively with mode `0600`. DCR may create
either supported client class and returns a confidential secret only in the
creation response.

Parse HTTP Basic credentials using RFC 6749 form-decoding. Reject malformed
Basic headers, multiple authentication methods, confidential credentials in the
body, and a Basic client identifier that conflicts with request data. Verify
confidential authentication before authorization-code consumption.

## Not in scope

- `client_secret_post`, private-key JWT, mTLS, DPoP, refresh tokens, device flow,
  secret recovery, or overlapping active secrets.
- DCR default enablement and IP rate limiting; M0.4 owns that endpoint posture.
- Redirect normalization and adapter-neutral code consumption; M0.3a/M0.3b own
  those mechanisms.
- An administrative web UI or automatic credential delivery to third parties.

## Target files/API

- `app/models/hitch/client.rb`: add client class, digest/timestamp validations,
  `register_confidential!`, and transactional `rotate_secret!` while preserving
  `register!` for public/DCR registration.
- `app/models/hitch/client/credentials.rb` (new): immutable return value with
  `client` and `client_secret` readers; redact `inspect`/`to_s` and reject
  `to_h`/implicit JSON serialization so console, exception, and assertion output
  cannot reveal the secret.
- `app/controllers/hitch/tokens_controller.rb`: parse Basic authentication and
  select the public or confidential validation path before code consumption.
- `app/controllers/hitch/registrations_controller.rb`: accept only `none` or
  `client_secret_basic` and emit the RFC 7591 one-time secret fields only on
  confidential creation.
- `app/controllers/hitch/metadata_controller.rb`: advertise both implemented
  token endpoint authentication methods and no others.
- `db/migrate/*_add_confidential_credentials_to_hitch_clients.rb` (new): add
  `token_endpoint_auth_method`, `client_secret_digest`,
  `client_secret_issued_at`, and `client_secret_rotated_at` with indexes or
  constraints required by the model contract. Use explicit reversible `up` and
  `down`; database checks restrict the method to the two supported values and
  require digest/issued-at exactly for confidential records.
- `lib/tasks/hitch.rake`: add both operator tasks and the TTY/file-output safety
  boundary.
- `lib/hitch/engine.rb`: filter `client_secret` and Authorization-derived secret
  fields from parameter logging.
- `bin/conformance-auth` and `test/conformance/authorization/` (new in this
  issue): pin and run official metadata plus the reviewed resource-aware public
  and confidential grant extension. The extension stays visibly separate from
  official runner output.
- `test/integration/confidential_client_test.rb` and
  `test/tasks/hitch_clients_test.rb` (new), plus metadata/DCR regression tests.

The four operator methods/tasks and credentials readers are public M0 API and
must enter M0.5's manifest. Digest helpers and Basic parsing remain private.

## Dependencies

- M0.1 is complete and its public-client regression suite remains green.
- H0's `bin/ci-test` is the test dispatcher. This issue itself creates the
  conformance command, conformance fixtures, migration, tests, and evidence
  directories named below.

## Acceptance commands

Run:

```sh
bin/ci-test test/integration/confidential_client_test.rb \
  test/tasks/hitch_clients_test.rb \
  test/integration/oauth_flow_test.rb
bin/conformance-auth --profile metadata
bin/conformance-auth --profile resource-aware-grants
bin/rubocop
```

The issue creates every new test and `bin/conformance-auth` before running these
commands. Tests must cover successful public/confidential exchanges, bad and
malformed Basic credentials returning 401 `invalid_client`, duplicate auth
methods, create/rotate invalidation, concurrent rotation, one-time DCR fields,
and unchanged public-client behavior. Task canaries must prove TTY-only display,
exclusive `0600` file creation, refusal to overwrite, exactly one disclosure,
and zero secret bytes in stdout, Rails logs, exception text, or database
plaintext.

## Evidence paths

Create:

- `docs/evidence/0.1.0/auth/confidential.json` for test/task outcomes and
  redacted canary checks;
- `docs/evidence/0.1.0/auth/official-metadata.json` for unmodified runner output;
- `docs/evidence/0.1.0/auth/resource-aware-grants.json` for the Hitch extension;
  and
- `docs/evidence/0.1.0/auth/resource-aware-grants.patch` for its reviewed delta
  from the pinned upstream vector.

Record hashes and outcomes, never plaintext secrets, Basic headers, codes,
verifiers, or tokens. Credential-bearing raw runner output remains ephemeral
and is destroyed; CI retains only sanitized summaries and raw-file hashes.

## Rollback

R1/R2: revert controllers, tasks, and public API while retaining additive
columns if any confidential record could exist. Before checkpoint acceptance,
an empty development schema may reverse the migration normally. After use, forward-patch
or leave nullable columns dormant; never restore an old digest as an active
secret.

## Estimate

Four engineering days. Risk is high because this adds a credential lifecycle,
public operator surface, migration, and token-boundary authentication.

## Risks

- Plaintext can escape through task output, inspection, exceptions, parameter
  logs, test failures, or DCR serialization.
- Basic client identifiers require form-decoding before lookup; ordinary Base64
  parsing alone is incorrect.
- Retrying or serializing the credentials value can accidentally disclose the
  one-time secret more than once.
- Rotation and token exchange races must never accept both old and new secrets
  after the rotation transaction commits.

## Owner

The Hitch release maintainer is accountable and must review secret-handling
evidence. Implementation may be delegated, but conformance labeling and any
credential-bearing manual exercise require release-maintainer supervision.
